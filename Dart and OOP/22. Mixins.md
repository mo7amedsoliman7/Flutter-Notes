## What are Mixins?

Mixins are a way to **reuse code across multiple class hierarchies** without inheritance. They provide a form of multiple inheritance in Dart.

---
## Defining a Mixin

Use the `mixin` keyword.

```dart
mixin Flyable {
  void fly() => print('$runtimeType is flying');
}

mixin Swimmable {
  void swim() => print('$runtimeType is swimming');
}
```

---
## Using Mixins — `with` Keyword

```dart
class Animal {
  String name;
  Animal(this.name);
}

class Duck extends Animal with Flyable, Swimmable {
  Duck(String name) : super(name);
}

void main() {
  var duck = Duck('Donald');
  duck.fly();   // Duck is flying
  duck.swim();  // Duck is swimming
}
```

---
## Mixin with `on` Constraint

Restrict a mixin to only be used on certain classes.

```dart
mixin Musical on Performer {
  void playInstrument() => print('Playing...');
}

class Performer {
  void perform() => print('Performing');
}

class Musician extends Performer with Musical {}

// class Robot with Musical {} // ❌ Error: Musical requires Performer
```

## Mixins vs Inheritance vs Interfaces

| Feature | `extends` | `implements` | `with` (mixin) |
|---|---|---|---|
| Reuses implementation | ✅ | ❌ | ✅ |
| Multiple use | ❌ (one parent) | ✅ (many) | ✅ (many) |
| Requires re-implementation | ❌ | ✅ | ❌ |
| Has constructor | ✅ | N/A | ❌ |
| Can have state/fields | ✅ | N/A | ✅ |
| Relationship type | Inheritance (`is-a`) | Contract/API | Shared behavior |
| Typical use | Base class hierarchy | Enforce structure | Reusable features/logic |

---
## Mixin Order Matters

Later mixins override earlier ones if methods conflict.

```dart
mixin A {
  String greet() => 'Hello from A';
}

mixin B {
  String greet() => 'Hello from B';
}

class C with A, B {} // B wins — last mixin takes precedence

void main() {
  print(C().greet()); // Hello from B
}
```
