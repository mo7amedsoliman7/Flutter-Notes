## What is Error Handling?

Error handling lets your program **gracefully recover** from unexpected situations instead of crashing.

---
## `try` / `catch` / `finally`

```dart
void main() {
  try {
    int result = 10 ~/ 0; // integer division by zero
    print(result);
  } catch (e) {
    print('Caught: $e');
  } finally {
    print('Always runs — cleanup here');
  }
}
```

---
## `on` — Catch Specific Exception Types

```dart
void readFile(String path) {
  try {
    // simulate file read
    throw FormatException('Invalid file format');
  } on FormatException catch (e) {
    print('Format error: ${e.message}');
  } on IOException catch (e) {
    print('IO error: $e');
  } catch (e, s) {
    print('Unknown error: $e');
    print('Stack trace: $s');
  }
}
```

---
## `throw` — Throwing Exceptions

```dart
double divide(double a, double b) {
  if (b == 0) throw ArgumentError('Cannot divide by zero');
  return a / b;
}
```

You can throw any non-null object, but using `Exception` or `Error` subclasses is best practice.

---
## Custom Exceptions

```dart
class InsufficientFundsException implements Exception {
  final double amount;
  final String message;

  InsufficientFundsException(this.amount)
      : message = 'Insufficient funds: need \$$amount more';

  @override
  String toString() => message;
}

class BankAccount {
  double _balance;

  BankAccount(this._balance);

  void withdraw(double amount) {
    if (amount > _balance) {
      throw InsufficientFundsException(amount - _balance);
    }
    _balance -= amount;
  }
}

void main() {
  try {
    BankAccount(100).withdraw(200);
  } on InsufficientFundsException catch (e) {
    print(e); // Insufficient funds: need $100.0 more
  }
}
```

---
## `Error` vs `Exception`

| Type | `Exception` | `Error` |
|---|---|---|
| Purpose | Recoverable runtime issues | Programming mistakes / invalid state |
| Should you catch it? | ✅ Usually yes | ❌ Usually no |
| Indicates | External or expected failure | Bug in the code |
| Examples | `FormatException`, `IOException` | `AssertionError`, `StackOverflowError` |

---
## `rethrow`

Re-throws the current exception to let a higher-level handler deal with it.

```dart
void process() {
  try {
    riskyOperation();
  } catch (e) {
    log(e); // log locally
    rethrow; // let caller handle it
  }
}
```

---
## Notes

- `finally` always runs — even if an exception is thrown or `return` is called
- Avoid catching `Error` — these indicate bugs that should be fixed, not swallowed
- Prefer specific `on` clauses over a bare `catch` for clarity
