# ISP

> **No class should be forced to depend on methods it doesn't use.** Prefer several small, focused interfaces over one big "fat" interface, so each implementer only commits to what it actually does.

The giveaway: classes that implement an interface and leave some methods empty, or throw `UnimplementedError`, just to satisfy the compiler.

---
## Example : Services split by role

### ❌ Violating ISP

```dart
abstract class AuthService {
  Future<void> login(String email, String pass);
  Future<void> logout();
  Future<void> register(String email, String pass);
  Future<void> resetPassword(String email);
  Future<void> verifyPhone(String code);
  Future<void> signInWithGoogle();
}

// A mock for a login-only test must implement all six methods
```

### ✅ Following ISP

```dart
abstract class LoginService {
  Future<void> login(String email, String pass);
  Future<void> logout();
}

abstract class RegistrationService {
  Future<void> register(String email, String pass);
  Future<void> verifyPhone(String code);
}

abstract class PasswordService {
  Future<void> resetPassword(String email);
}

abstract class SocialAuthService {
  Future<void> signInWithGoogle();
}

class LoginCubit extends Cubit<LoginState> {
  final LoginService auth; // only sees login/logout
  LoginCubit(this.auth) : super(LoginInitial());
}
```

Mocks stay tiny, and `LoginCubit` can't touch registration logic by mistake.

---
## Why it matters

- **Smaller mocks and fakes:** tests implement 1-2 methods instead of 10.
- **Fewer ripple changes:** editing `PasswordService` doesn't recompile or retest login code.
- **Clearer intent:** the type of a dependency tells you exactly what the class does with it.
- **Supports LSP:** no more `UnimplementedError` overrides breaking substitutability.

## Common pitfalls

- **Don't create one interface per method.** Group methods that are always used together (`login` and `logout` belong side by side).
- **Don't split before you feel the pain.** If every implementer genuinely uses every method, the interface is fine.
- **Don't confuse ISP with SRP.** SRP is about why a _class_ changes; ISP is about what a _client_ is forced to depend on.

## Quick self-check

Ask: _"Does any implementer leave a method empty or throw `UnimplementedError`?"_

- No → ✅
- Yes → split the interface ❌
